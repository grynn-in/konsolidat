## What this is

A way for any group to onboard onto konsolidat / konsol without touching Desk forms one by one:

1. fill `Konsolidat_Onboarding_Template.xlsx` (one sheet per konsol doctype, headers = fieldnames);
2. put one trial-balance file per period in a folder (konsol's bulk-upload format);
3. run `konsol_load.py`, which writes it all through `frappectl`;
4. `konsol schema apply --run-dbt` (konsol-cli) or a Pipeline Run.

`examples/aquila/` is a complete filled example sized like a mid-cap group, used to prove the shape:
46 entities, 10 currencies, 238 accounts, 6 dimensions / 3 hierarchies, 12 periods of balanced trial balances.

## Files

| File | Role | Edit? |
|------|------|-------|
| `konsol_template.py` | The sheet schema (`SHEETS`, `LOAD_ORDER`, `TB_HEADER`) and the workbook writer. Both scripts import it. | Yes — change a column here and template, example and loader move together. |
| `build_workbooks.py` | Chart, entities, dimensions, hierarchies, FX, ownership, the operating model that generates the trial balances; writes template + example. Deterministic (seeded by code). | Yes — then `uv run build_workbooks.py`. |
| `konsol_load.py` | Reads a filled workbook + TB folder, calls `frappectl`. | Yes. |
| `Konsolidat_Onboarding_Template.xlsx` | Generated. | No — regenerate. |
| `examples/aquila/Aquila_Group_Master_Data.xlsx`, `examples/aquila/tb/TB_*.xlsx` | Generated. | No — regenerate. |
| `README.md` | User-facing guide (sheets → doctypes, quick start, conventions). | Yes. |

Python ≥ 3.10 and `openpyxl` (PEP 723 header: `uv run <script>` works). No LibreOffice needed: the workbooks hold no formulas.

## Design decisions (and why)

- **frappectl, not konsol-cli.** Since konsol#379 konsol-cli has only `config export/diff/apply` (semantic-model bundle) and
  `schema apply/status`. Entities, chart, groups, rates and trial balances are ordinary documents → `frappectl doc create/update/submit`,
  `file upload`, `method call konsol.tb_bulk.check_file / load / get_upload`.
- **Sheet headers are fieldnames**, not labels, so each sheet is also importable through Desk → Data Import. Three things are loader-only:
  `parent_group` (Consolidation_Groups), `parent_member_code` (Reporting_Hierarchy_Members) — both resolve a code to a Frappe name
  the user should not have to know — and `Fiscal_Periods`, which the loader nests into its EPM Fiscal Year as the `periods` child table.
- **Trial balances are separate files**, never a sheet in the master workbook: konsol's bulk loader reads the FIRST sheet of an xlsx, and
  one file per period mirrors how groups actually upload. The master workbook's `Trial_Balance` sheet is a 60-row format reference.
- **Period-end balance basis** for the example (`amount_basis` on every row and `default_amount_basis` in Settings). That is why the
  calendar has a Closing period (13) and the chart exactly one `is_retained_earnings` account (3300): the warehouse synthesises the
  FY2025 year-end close there. FY2025 P12 carries the year's P&L in its accounts; every FY2026 file carries RE = opening RE + FY2025 result.
- **Consolidation tree:** group nodes have blank `data_area_id` (root `AQUILA` in EUR, sub-groups `AQ_EU/AQ_UK/AQ_US/AQ_IN` in
  EUR/GBP/USD/INR); the holding companies (AQH, AQEU, …) are entity nodes under them. Sub-groups contain only same-currency entities, so
  only X→EUR rates are needed. Policy fields and journal accounts sit on the root only; `ic_difference_account` 6750 on every group node.
- **Ownership** lives only on Ownership_Periods (dated); root takes no row; sub-group nodes take a row with blank `data_area_id`.
- **Deals are sheets, and load last.** Business Combinations and Business Disposals are six sheets (two parents, four child tables
  joined by a loader-only `deal_ref`; `Sheet.parent_sheet` / `Sheet.table_field` let `konsol_load.py` nest them generically, like
  Fiscal_Periods) rather than Desk-only forms, so an example group can declare an acquisition and a disposal in the same workbook.
  They sit after Historical_Equity_Rates in LOAD_ORDER because approval needs the Closing rate of the deal's period, the root's
  policy and journal accounts, and (for a disposal) the submitted Ownership Period it ends; a combination creates the acquired
  entity's Ownership Period itself, so Ownership_Periods must not carry one. The acquired balance sheet is the balances at the last
  period-end before the acquisition period (konsol#406). The Aquila example declares no deals: its six deal sheets are empty.
- **Intercompany** is generated from the payer/borrower side in its own currency and mirrored on the counterpart at the governed
  rates (monthly Average for flows, Closing for balances). Receivables = payables to the cent after translation; flows differ only by
  average-vs-closing, which is what the 6750 difference account is for. Loans are denominated in the borrower's currency; the lender
  revalues through 7140/7240.
- **Cash (1241) is the balancing plug** in FY2026 files, retained earnings in the FY2025 P12 file. A negative plug becomes an overdraft
  (2241) plus a 1 %-of-revenue cash floor. Cost ratios were tightened once (cogs 0.52–0.66, opex 0.15–0.23) so most entities are profitable.
- **Dimension names** are `dim_` + lower snake case because konsol refuses anything else for `in_trial_balance` dimensions and uses the
  name verbatim as the file header. `survives_close` is left 0: konsol refuses it ticked (konsol#255).
- **Template example rows carry `EXAMPLE_` codes**; the loader refuses them unless `--allow-examples`.

## Likely to bite on first live run

- `frappectl doc list --json` return shape: the loader accepts a list or `{"data": [...]}` / `{"message": [...]}`; adjust `Frappectl.list` if it is something else.
- `konsol.tb_bulk.check_file` report shape: `load_trial_balances` guesses `ready` / `status` / `problems` / `entity` keys from
  `tb_bulk_model.check_group`. Read `konsol/tb_bulk_model.py` (`check_group`, `read_state`) and align the field names.
- `get_upload` polling reads `status_now` (konsol#332-2) then `status`; terminal states assumed `Loaded / Partly Loaded / Failed / Cancelled`.
- Creating Main Accounts with `status: Published` directly needs EPM Admin and publishes parents first (loader orders parents first);
  if konsol insists on Draft-then-publish, create Draft and call the `publish` doctype method instead.
- Dimension Mapping rows for US01 are `Draft` (connector-only; the example is upload-only) — fine, just noise.
- Group Exchange Rate create then submit: submit is the approval; period must be declared (fiscal years load first) and open.
- Equity-method associate (ES03, 40 %) and proportional JV (DE04, 50 %) upload full trial balances; check what the warehouse does with
  `consolidation_method = equity / proportional` — it may be unimplemented and those two may need `none` or exclusion.
- FY2025 has no trial balances for P1–P11; `assert_year_end_close_declared` needs a Closing period after the last claimed period (P12 < CLS 13) — satisfied.

### 7 Nov 2026, later: first konsol-driven build on the live site failed on dimension source columns

`bronze_budget_transaction_lines` and `bronze_general_journal_account_entries` read
`vars.dimensions[].source_column` from `epm_staging.stg_budget_entries` / `stg_gl_entries`,
whose columns are `dim_<dimension_name>`. The example declared D365-style source columns
(`BusinessLine`), as the template text invited ("any text for upload-only sites"), so the
build failed with UNKNOWN_IDENTIFIER and the whole consolidation chain was skipped.
Fixed in the example (source_column = dimension_name) and in the template text.
Product finding: on an upload-only site konsol should default `source_column` to the
dimension name, or the bronze models should not depend on it when no connector exists.
Not yet filed as an issue.

### 7 Nov 2026, later: live build against the replica

First complete konsol-driven build (Build Approval BAPR-00003, dbt 61 s, 1 warning):

differed, all from one cause: the generator declared historical equity rates with 8

regenerated and the site is being reloaded to the published files (cancel 138
submissions + CJ, re-upload, rebuild) so the published example and the site agree
to the cent.

dbt warning `assert_declared_historical_has_a_rate`: 156 rows = 6 EUR entities × 2
equity accounts × 13 periods. An entity whose functional currency is the group
currency needs no historical rate (it is 1); the test should exclude same-currency
entities. Product finding, not yet filed.

Reloading 13 files back-to-back: the `konsol.tb_bulk.load` call for P6 failed with MariaDB
1213 (deadlock) while the P5 load job was still committing its submissions; the upload
stayed "Checked" and was loaded by hand. The loader now retries a deadlocked load once
after 10 s. Product finding: the load endpoint and the running load job contend on shared
rows (Build Approval debounce or period rows); not yet filed. The loader also reports
"Not permitted" on every load call although each load runs to completion; traceback
being captured with `frappectl --debug`.
